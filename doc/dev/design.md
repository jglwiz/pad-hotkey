# PadHotkey 设计

## 目标与取舍

2026-11-23：用户决定用 C# 实现本机 REST API 驱动的手柄快捷键工具。XInput 读取 Q37 Pro 接收器，HIDMaestro 2.3.0 输出虚拟键盘，替代 AntiMicroX 和 Python/pythonnet 原型。选择 C# 是为了直接调用已验证的 SDK；Native AOT 不作为第一版功能交付的前提。

单进程使用 ASP.NET Core Slim Builder，无数据库和 WebView。第一版提供后台进程和 CLI，托盘菜单、多配置自动切换、完整 OpenAPI 和 AOT 发布尚未实现。`/v1/schema` 是能力发现而非标准 JSON Schema。

## 通用配置边界

2026-11-24 用户明确要求通用工具不预设个人快捷键。移除 Core 中的个人预设工厂，缺少 profile.json 时仅创建空 Profile；config/vibe.json 仅作为可选示例，不自动读取。

当前配置使用 GET/PUT /v1/profile 和 PUT /v1/profile/bindings/{id}。name 仅是标签，不决定路由；CLI 和能力发现同步修改，不保留场景专用路由别名。已有用户 JSON 原样加载，避免升级覆盖配置。

## 状态约束

引擎通过单个锁串行处理设备 Tick、配置更新、诊断和暂停。v0.1.2 按用户要求在启动时直接启用保存的映射，可用 --paused true 显式暂停；首次启动、重连、恢复或改配置后，输入必须先回到释放阈值才重新触发。摇杆使用原始轴值复位，方向互斥；不能把失去主方向当作回中，否则斜推抖动会重复触发。

tap 按修饰键 → 主键 → 释放主键 → 释放修饰键，每阶段至少 100ms；单键 tap 保持 100ms。该时序来自豆包虚拟键盘历史测试，暂不为低延迟缩短。hold 直接跟随按钮状态；不同绑定持有的键求并集。硬件键盘与虚拟键盘的组合仍可能相互影响。

映射配置验证后以文件替换方式保存，保留每次旧版本。If-Match 避免多个 agent 覆盖彼此改动。输出失败时进入暂停故障态，要求排除原因后重启；应用失败尝试恢复旧配置文件，回滚失败会明确报错。配置更新不能被描述为目标应用行为已生效。

## 权限与边界

HID 模式需要管理员权限，不自动安装或升级驱动；固定已有 UMDF2 后端。HIDMaestro 创建上下文仍有自身的后台预热行为。运行前拒绝同时运行 AntiMicroX，使用会话级单例防止本工具重复发键。

API 仅绑定 127.0.0.1，所有接口验证本机随机令牌，拒绝带 Origin 的浏览器请求并检查 Host。数据目录 ACL 限制当前用户、管理员与 SYSTEM。API 只支持映射和受限诊断，不提供命令执行。事件保存在有界内存队列中，不记录实体键盘或语音。令牌不进入命令行、公共配置或日志。

虚拟键盘按 HID US 物理键位编码；非 US 布局下符号可能不同。XInput 仅绑定明确索引，重连后的索引不等于实体身份，不能自动认定同槽位永远是同一手柄。

正常断连、暂停、诊断超时及退出主动释放按键。强制终止进程的效果依赖 SDK/驱动清理机制，需单独验证；不能用 finally 证明强制退出安全。

## 验证入口

`tests/PadHotkey.Tests` 覆盖边界、滞回、焦点、组合键和失败释放；`tests/api_smoke.py` 验证 dry-run 服务。实测结论见 [验证记录](verification.md)。
